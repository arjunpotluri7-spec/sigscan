# Contributing to Sigscan

Thanks for helping. Sigscan is a small, defensive, read-only scanner; contributions that keep it
small, readable and safe are very welcome.

## Development setup

You need a C++20 compiler (clang 16+ or GCC 12+), Ninja and Python 3. CMake, clang-format and
clang-tidy are pinned in `tools/requirements.txt`; install them into a local virtual environment:

```bash
python3 -m venv .tools
.tools/bin/pip install -r tools/requirements.txt
export PATH="$PWD/.tools/bin:$PATH"
```

## Build, test, lint

```bash
cmake --preset dev && cmake --build --preset dev && ctest --preset dev     # warnings are errors
cmake --preset asan && cmake --build --preset asan && ctest --preset asan  # ASan + UBSan
./build/asan/fuzz/fuzz_smoke_rule_parser fuzz/corpus/rule_parser 20000
./build/asan/fuzz/fuzz_smoke_matcher fuzz/corpus/matcher 20000
./tools/lint.sh                                                            # clang-format + clang-tidy
```

On Linux with clang you can also run the coverage-guided fuzzers:

```bash
cmake --preset fuzz && cmake --build --preset fuzz --target fuzz_rule_parser fuzz_matcher
./build/fuzz/fuzz/fuzz_rule_parser -max_total_time=60 -dict=fuzz/rules.dict fuzz/corpus/rule_parser
```

CI runs all of the above on Ubuntu and macOS (see `.github/workflows/ci.yml`).

## Style

- C++20, library in `src/lib` with public headers in `include/sigscan/`, and a thin CLI in
  `src/cli`. Format with the repository `.clang-format`; keep clang-tidy clean. Any `NOLINT`
  needs a short reason next to it.
- No raw pointer arithmetic over input bytes: use `std::span`, explicit length checks and checked
  integer math for offsets and sizes.
- Comments explain *why*, not *what*.
- No network calls, subprocesses, or execution of scanned content, ever.

## Tests

Every change needs tests. Parser changes need a test for the new construct and for each new
error message (including its `line:col`). Matcher changes must keep the Aho-Corasick engine in
agreement with the naive matcher (`Ruleset.AhoCorasickAgreesWithNaiveOnRandomInputs`) and should
add a fuzz seed if they touch new code paths.

## Samples

Sample data must be synthetic and harmless: fictional marker strings, documentation IP ranges
(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and `example.com/org/net` domains. Never add
real malware, EICAR, or strings copied from real malware. Sample files are generated by
`samples/generate.py`; edit the script and regenerate rather than editing files by hand
(`ctest` checks that they match).
